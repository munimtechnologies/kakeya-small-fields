## Summary

U*(n) is the least size of a sticky Kakeya set in F_3^n. In a sticky family, coordinate j of
the base point P(d) of the line in direction d depends only on d_1, ..., d_j. The classical
set {0,1}^n ∪ {0,2}^n is sticky and has 2^(n+1) - 1 points. a186 proved that it is the
smallest sticky set for n <= 3 (U* = 3, 7, 15) and that 29 <= U*(4) <= 31. Question S5 asked
whether it is always the smallest.

1. **Theorem 76.** There is a sticky Kakeya set in F_3^4 with 30 points, so **29 <= U*(4) <= 30**.
   The set is listed in full below.
2. **Lemma 160 (colour lifting).** Colour the points of a sticky Kakeya set K in F_3^n with
   three colours so that every line of its family shows exactly two colours. Then F_3^(n+1)
   has a sticky Kakeya set with exactly 2|K| + 1 points that again has such a colouring.
3. **Theorem 77.** For every n >= 4, U*(n) <= 31 · 2^(n-4) - 1 < 2^(n+1) - 1. So **the
   classical set is a smallest sticky Kakeya set exactly for n <= 3**. Question S5 has a
   negative answer, first at n = 4.

The 30-point set realises a186's game witness (7, 7, 13) exactly. The game relaxation
(a183-a185) predicted cheap sticky trees; this is the first real set below the classical one.
The saving is a constant factor of 31/32, so the growth rate of U*(n) stays between
1.90499 (a183) and 2.

## 1. The construction (Theorem 76)

Recall Theorem 74 (a186). Take a sticky Kakeya set K' in F_3^(n-1), a full sticky tree T of
height n - 1 with slices S_t(T) = {P_T(d) + t d : d ∈ F_3^(n-1)}, and a slice index h. Then
there is a sticky Kakeya set in F_3^n with |K' ∪ S_h(T)| + sum_{t != h} |S_t(T)| points.
The classical set takes T with three slices of 2^(n-1) points each and S_h ⊂ K'.

**Three trees of height 2** (coordinates (y_3, y_4), directions f = (f_1, f_2)):

| tree | P(f) | S_0 | S_1 | S_2 |
|---|---|---|---|---|
| Y | (-f_1, 0) | {(a,0)} (3, a "graph") | {0} × F_3 (3, a "row") | F_3^2 (9) |
| X | (1, -f_2) | {1} × F_3 (3) | {(a,0)} (3) | F_3^2 (9) |
| Z | (f_1^2, -f_1 f_2) | {1} × F_3 ∪ {(0,0)} (4) | {0} × F_3 ∪ {(2,0)} (4) | {0} × F_3 ∪ {(2,0)} (4) |

**The tree T of height 3** (coordinates (y_2, y_3, y_4)) has root map x ↦ x^2 and subtrees
Y, X, Z under x = 0, 1, 2. Point P_T(e) + t e lies in the plane y_2 = e_1^2 + t e_1:

- t = 0: plane 0 gets Y_0 (3 points); plane 1 gets X_0 ∪ Z_0 = Z_0 (4), because X_0 ⊂ Z_0. Total 7.
- t = 1: plane 0 gets Y_1 ∪ Z_1 = Z_1 (4), because Y_1 ⊂ Z_1; plane 2 gets X_1 (3). Total 7.
- t = 2: plane 0 gets Y_2 ∪ X_2 = F_3^2 (9); plane 2 gets Z_2 (4). Total 13.

The game vector of T is (7, 7, 13): the triangle witness of a186 over (3,3,9), (3,3,9) and
(4,4,4). Here the game's "max" merges really happen, because the row slices of X and Y lie
inside the row-plus-point slices of Z.

**K' in F_3^3** is Theorem 74's construction from K'' (the lines through the origin of F_3^2),
the tree Y, hidden slice 2 and shift 0. Its planes y_2 = 0, 1, 2 hold F_3^2 (9 points),
the graph {(a,0)} (3) and the row {0} × F_3 (3): 15 points, a smallest sticky set in F_3^3.

**The set.** Take K', T, h = 2 and w = 0. Then K' ∪ S_2(T) has 9 + 3 + 4 = 16 points (the
row {0} × F_3 of K' lies inside Z_2), and the other two slices have 7 each:

  |K| = 16 + 7 + 7 = 30.

In coordinates (y_1, y_2, y_3, y_4), K is

- y_1 = 0: all nine points (0,0,a,b); (0,1,a,0) for a ∈ F_3; (0,2,0,b) for b ∈ F_3, and (0,2,2,0).
- y_1 = 1: (1,0,a,0) for a ∈ F_3; (1,1,0,0), (1,1,1,0), (1,1,1,1), (1,1,1,2).
- y_1 = 2: (2,0,0,b) for b ∈ F_3, and (2,0,2,0); (2,2,a,0) for a ∈ F_3.

The node maps of the family are `family_K4()` in `sticky_break.py`. The tests rebuild the set
from the maps, check that every one of the 80 directions has its line inside it, and check
the count 30 and the plane sizes 16, 7, 7.

## 2. Colour lifting (Lemma 160)

Read the three colours as the three 2-subsets {0,1}, {0,2}, {1,2} of F_3. Call a colouring of
K **good** if every line of the family shows exactly two colours.

*Labels.* A map g(z) = a z^2 + b z + c with a != 0 takes exactly two values on F_3 for each
t, as z ↦ g(z) + t z. For the one t with b + t = 0 they are {c, c + a}; for the other two
they are {c, c - a}. Any two distinct 2-subsets X, Y of F_3 meet in one element c, and then
Y = {c, c + a} and X = {c, c - a} for a = y - c. So for each pattern (X, X, Y), with Y at any
of the three positions, some g gives exactly that pattern. An affine g gives a singleton and
F_3 twice instead.

*Lemma 160.* Let K ⊂ F_3^n be the Kakeya set of a sticky family P with a good colouring col,
and let P_0 = P(0) (a point of K). For each d != 0, choose g_d so that
{g_d(z) + t z : z} = col(P(d) + t d) for t = 0, 1, 2. Set P^+(d, z) = (P(d), g_d(z)) and
P^+(0, z) = (P_0, 0). This family is sticky, and its Kakeya set K^+ has fibre col(p) over every
p != P_0 and fibre F_3 over P_0. Hence |K^+| = 2|K| + 1. Colour (p, γ) by col(p), except the
single point of the fibre over P_0 outside col(P_0), which gets another colour. Every lifted
line shows the colours of the line below it (two). The vertical line over P_0 shows
col(P_0) twice and the other colour once. So the colouring is good. ∎

Lifting F_3 (coloured X, X, Y) again and again gives sticky sets of the classical size
2^(n+1) - 1 in every dimension. Starting instead from the 30-point set saves one point in
dimension 4, and the saving doubles with each lift.

## 3. Theorem 77

The 30-point set has a good colouring:

- planes y_1 = 1 and 2: colour {0,1};
- plane y_1 = 0: the point (0,0,0,0) and the three points (0,1,a,0) get {0,2}; every other
  point gets {1,2}.

*Check.* Every line in a direction with d_1 != 0 meets each plane y_1 = u once. Its points
in planes 1 and 2 are coloured {0,1}, and its point in plane 0 is not. The lines of K' with
d_2 != 0 meet (0,1,·,·) ({0,2}), (0,2,·,·) ({1,2}) and (0,0,·,·) (either). The lines of
K'' pass through (0,0,0,0) ({0,2}) and two points of colour {1,2}. The tests check all 80
directions.

Lifting gives sticky Kakeya sets with 61, 123, 247 points in dimensions 5, 6, 7, and in
general 31 · 2^(n-4) - 1. Each is checked by `test_sticky_break.py` (to n = 6, with the
Kakeya property and the colouring) and `results/sticky_break.json` (to n = 7). With
Theorem 75:

| n | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|---|---|---|---|---|---|---|---|
| classical 2^(n+1) - 1 | 3 | 7 | 15 | 31 | 63 | 127 | 255 |
| this note, upper bound on U*(n) | - | - | - | 30 | 61 | 123 | 247 |
| exact U*(n) | 3 | 7 | 15 | 29 or 30 | ? | ? | ? |

## 4. What it means

- **Stickiness does not force the classical size.** Theorem 75 shows the classical set is
  optimal up to dimension 3. From dimension 4 on, there is always something smaller.
- **The game was pointing the right way.** a185 showed that the selection game has trees
  cheaper than 2^h. a186 left open whether real slices can nest well enough. At height 3 they
  can, for the (7, 7, 13) witness.
- **What stays open.** (S6) Is U*(4) = 29 or 30? The pre-registered job `sticky-exact-v1`
  (`notes/prereg-sticky-exact.md`, written before this note and not yet run) decides it. Its
  rule S4-BREAK is now known to hold: our set has 30 points. Its n = 5 rule S5-BREAK (a
  sticky set of at most 62 points) holds too, by the 61-point lift. (S7) Is the growth rate
  of U*(n) below 2? Lemma 160 only doubles, so a base below 2 needs better trees at every
  height, not just one saving at height 3. The cheapest game trees (a185) show where to look.
- **Kakeya sets in general.** Nothing changes for all Kakeya sets: F_3^4 has 27-point Kakeya
  sets (kakeya-conjecture v1.1.0), and a186's Corollary 75.1 (the smallest Kakeya sets in
  F_3^3 and F_3^4 are not sticky) still holds, because U*(4) >= 29.

## Method note

The set was found by hand during this run, before any computer search, by combining Theorem
74's plane split with the shapes of the 3- and 4-point slices of height-2 trees (rows, graphs,
and a row plus a point). No code was run while it was being found. The published tests are
the first machine check.

## Prior art

As in a182-a186: we know of no earlier definition or study of sticky Kakeya sets over finite
fields beyond the classical product construction. A search on 2026-11-19 found "sticky" only
in the Euclidean setting (Wang and Zahl, arXiv:2210.09581). Pointers are welcome at
mv2@munimtech.com.
