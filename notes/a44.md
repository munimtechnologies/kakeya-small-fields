Using m42b's own A_u (m53 used another matrix of its pair orbit, which is a single class of A_u)
means the 178 instances refine exactly the class that m42b left UNKNOWN. The code reuses m53.py
unchanged for the instance and the solver loop, so a bug there would show in both jobs' positive
controls.

The rule, written before either batch ran (in full in m54-predictions.md): if m53 has closed
fewer than 30 of its 40 instances before m54a starts, m54a is superseded and the third-matrix
split is counted by hand first; batch a with at least 60 of 89 UNSAT and no SAT queues batch b
(the open ones re-run with a 10-minute cap); fewer than 60 means a hand count first. All 178
UNSAT empties the kind-graph class (computer-assisted).
