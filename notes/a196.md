## Summary

**Theorem 79.** There is a full sticky tree G of height 5 over F_3 whose three slices have 31
points each. Its slice product is 31^3 = 29,791 < 8^5 = 32,768. Hence (Corollary 78.1) question S7
holds: the smallest sticky Kakeya sets in F_3^n grow with base

    beta_s <= 31^(1/5) = 1.98734...  < 2,

and with Theorem 72 (a183; Corollary 78.2 of a188), **1.90499 <= beta_s <= 1.98734**. The classical construction
(base 2) is not optimal among sticky Kakeya sets over F_3.

Also:

- **Proposition 91.** lim kappa_h^(1/h) = beta_s. So Conjecture T (a195) was equivalent to "S7 is
  false", and Theorem 79 refutes it: kappa_4 <= 31 < 32.
- **Proposition 92.** Every height-4 tree with kappa <= 31 has, up to the symmetries of Lemma 161,
  the root map x -> x^2, the isolated slice i = 0 and an offset w with first coordinate 0. Linear
  roots and the other two offsets give at least 32. With a195, kappa_4 is 30 or 31 and pi_5 lies in
  [27,000, 29,791].

The witness was found by hand while working through the case analysis behind Proposition 92, not
by the pre-registered search `sticky-kappa-v1` (still queued). That job will be graded against its
pre-registration as filed.

## 1. The construction

Notation as in a188: a tree of height k is a map P: F_3^k -> F_3^k whose coordinate j depends only
on d_1, ..., d_j, and S_t(P) = {P(d) + t d}. A root map g with children T_0, T_1, T_2 gives
S_t = union over x of {g(x) + t x} x S_t(T_x).

**A (height 3).** P_A(d) = (d1^2, -d1 d2, 0). Directly:

- A_0 = {(0,0,0)} u {(1,y,0)} (4 points);
- A_1 = A_2 = {(0,y,z)} u {(2,0,z)} (12 points: the plane x = 0 and one z-line in x = 2).

(This is a194's (4,12,12) tree with the roles of coordinates 2 and 3 exchanged; the z-line, not a
y-line, is what makes it fit inside B_2.)

**B (height 3).** a187's tree: root e1 -> e1^2 over the height-2 children Y(f) = (-f1, 0),
X(f) = (1, -f2), Z(f) = (f1^2, -f1 f2). Its slices are

- B_0 = {(0,y,0)} u {(1,0,0), (1,1,z)} (7 points);
- B_1 = {(0,0,z), (0,2,0)} u {(2,y,0)} (7 points);
- B_2 = {(0,y,z)} u {(2,0,z)} u {(2,2,0)} (13 points).

So **A_1 u A_2 is contained in B_2.**

**C (height 3).** P_C(e) = P_B(-e). Since S_t(P(-e)) = S_{-t}(P), C has slices (B_0, B_2, B_1) as
sets.

**H (height 4).** Root d1 -> d1^2 with children A, B, C under d1 = 0, 1, 2. The slice-t plane of
child x is x^2 + t x:

| slice | x = 0 (A) | x = 1 (B) | x = 2 (C) | slice of H |
|---|---|---|---|---|
| 0 | plane 0: A_0 | plane 1: B_0 | plane 1: C_0 = B_0 | {0} x A_0 u {1} x B_0: 4 + 7 = 11 |
| 1 | plane 0: A_1 | plane 2: B_1 | plane 0: C_1 = B_2 | {0} x (A_1 u B_2) u {2} x B_1: 13 + 7 = 20 |
| 2 | plane 0: A_2 | plane 0: B_2 | plane 2: C_2 = B_1 | {0} x (A_2 u B_2) u {2} x B_1: 13 + 7 = 20 |

So H has slices (11, 20, 20) and **H_1 = H_2**. Its product 4,400 is above pi_4 = 4,096 (a194), as
it must be, but kappa(H) = |H_0| + |H_1 u H_2| = 11 + 20 = 31 < 32 = 2^5.

**G (height 5).** The cyclic triangle of H (Proposition 89, i = 0, w = 0): root x -> x^2 over the
children H, H(d) + 2d and H(d) + d, whose slices are (H_t), (H_{t+2}) and (H_{t+1}). Then

- G_0 = {0} x H_0 u {1} x (H_2 u H_1): 11 + 20 = 31;
- G_1 = {0} x (H_1 u H_2) u {2} x H_0: 20 + 11 = 31;
- G_2 = {0} x (H_2 u H_1) u {2} x H_0: 20 + 11 = 31.

All maps used are sticky (each coordinate is a function of the earlier direction coordinates),
so G is a full tree of height 5 with slice product 29,791 < 32,768. ∎

*Proof of the base bound.* By Lemma 161 the product tree G^m (height 5m) has slices of 31^m
points, so sigma_{5m} <= 3 * 31^m, and Theorem 78 gives beta_s = lim sigma_k^(1/k) <= 31^(1/5).
Concretely, U*(n) <= U*(n-1) + sigma_{n-1} (Theorem 74) gives sticky Kakeya sets in F_3^n of size
O(31^(n/5)). The test suite also builds the 6-dimensional set {(t, G(d) + t d)} u {0} x K_5
(K_5 the classical recursive set) and checks by brute force that it contains a line in every
direction. ∎

How this sits next to the literature: for *general* Kakeya sets over F_3 the best known base is
3 * 2^(-2/3) = 1.8899 (Kopparty, Lev, Saraf and Sudan, random; explicit in this repository), and
the best lower bound is 1.8 (KLSS). Sticky sets need at least 1.90499^n points (a183), so they are
not the smallest Kakeya sets. Theorem 79 shows they are not stuck at the classical base 2 either.
We know of no other study of sticky Kakeya sets over finite fields.

## 2. Proposition 91 (Conjecture T was all of S7)

kappa_h <= sigma_h, because |A_{i+1} u (A_{i+2} + w)| <= |A_{i+1}| + |A_{i+2}|. By Corollary 89.1,
kappa_h >= pi_{h+1}^(1/3) >= tau^((h+1)/3) = beta_s^(h+1), where tau = inf pi_k^(1/k) and
beta_s = tau^(1/3) (Theorem 78). Since sigma_h^(1/h) -> beta_s, lim kappa_h^(1/h) = beta_s. So
kappa_h = 2^(h+1) for all h holds iff beta_s = 2, i.e. Conjecture T is equivalent to S7 failing.
(a195 presented T as a handle on S7; it was in fact the same question.) ∎

## 3. Proposition 92 (where a height-4 tree with kappa below 32 must live)

Let P be a height-4 tree with root g and children of height 3 with slices (A_t), (B_t), (C_t)
under x = 0, 1, 2. By the rotations rho_c we may take the isolated slice to be i = 0. The maps
-P (S_t -> -S_{-t}), P(d + e) (S_t -> S_t - t e, which only changes w) and P + v keep
min_w |S_0| + |S_1 u (S_2 + w)|, and normalise g to x^2 or to a linear map b x with b in {0, 1}.
Write w = (w_1, w'). We use pi_3 = 512 (a189), hence sigma_3 >= 24, and |S_s||S_t| >= 27 for any
two slices of a height-3 tree (d -> (P(d) + s d, P(d) + t d) is injective), hence any two slices
of one child have at least 11 points together.

- **g = x (slice 2 constant).** Slices 0 and 1 are spread over three planes, so
  |S_0| + |S_1 u (S_2 + w)| >= sum over children of (|T_0| + |T_1|) >= 3 * 11 = 33.
- **g = 0 (slice 0 constant).** |S_0| >= X := max_x |T^x_0|. In S_1 u (S_2 + w) child x's slice 1
  meets child y's slice 2 with y = 2x + w_1, an involution with one fixed point r. So the total is
  at least X + max(|T^r_1|, |T^r_2|) + |T^p_1| + |T^p_2| for another child p. Each child has
  |T_1||T_2| >= 512 / X, and checking X = 1, ..., 16 (and X >= 17 with |T_1||T_2| >= 27) gives at
  least 32 in every case (the minimum 32 occurs at X = 8 and X = 11).
- **g = x^2, w_1 = 1.** The planes give |A_0| + |B_0 u C_0| + |A_1 u C_1 u (C_2 + w')|
  + |A_2 u B_2| + |B_1| >= (|A_0| + |A_1| + |A_2|) + (|B_0| + |B_1|) >= 24 + 11 = 35.
- **g = x^2, w_1 = 2.** Similarly at least (|A_0| + |A_1| + |A_2|) + (|C_0| + |C_2|) >= 35.
- **g = x^2, w_1 = 0.** The value is
  |A_0| + |B_0 u C_0| + |A_1 u C_1 u (A_2 + w') u (B_2 + w')| + |B_1 u (C_2 + w')|,
  and Theorem 79's tree H is of this form with C = B(-e) and w' = 0.

So kappa_4 < 32 can only come from the last case, which is where the witness was found. ∎

## 4. What is open now

1. **The exact base.** 1.90499 <= beta_s <= 1.98734. Is kappa_4 = 30 (base 30^(1/5) = 1.9744)?
   The queued `sticky-kappa-v1` (simulated annealing for kappa at heights 3-6) and `sticky-h4r-v1`
   (a proved lower bound for pi_5) bear on this directly.
2. **Iterating the idea.** Theorem 79 is one instance of an operation on *pairs*: for height-h trees
   A, B and a translate with A_1 u A_2 inside B_2, root x^2 over (A, B, B(-e)) gives a tree with
   slices (|A_0| + |B_0|, |B_1| + |B_2|, |B_1| + |B_2|) and equal slices 1 and 2, so
   pi_{h+2} <= (|A_0| + |B_0| + |B_1| + |B_2|)^3. Applying it to H with itself gives only 62 at height
   6 (base 62^(1/6) = 1.9895). New pairs are needed to go below 31^(1/5).
3. **Sticky versus general.** The general Kakeya base over F_3 is at most 1.8899 (KLSS), below the
   sticky lower bound 1.90499 (a183), so sticky sets stay strictly worse than the best Kakeya sets;
   the sticky base is now known only to lie in [1.90499, 1.98734].

## Prior art

A fresh search (2026-11-20) found no work on sticky Kakeya sets over finite fields beyond the
classical product construction and this repository's notes. The finite-field Kakeya literature
(Dvir; Dvir, Kopparty, Saraf and Sudan; Kopparty, Lev, Saraf and Sudan; Bukh and Chao) concerns
general Kakeya sets. The sticky Kakeya theorem in R^3 (Wang and Zahl, J. Amer. Math. Soc. 39
(2026) 515-585) is the Euclidean analogue. Pointers are welcome at mv2@munimtech.com.
